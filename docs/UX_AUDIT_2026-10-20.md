# Auditoria UX/UI — AutoEditor Studio 2.6
Data: 2026-10-20

## Escopo e método

Revisão das versões **desktop React/FFmpeg** e **web React/Vite/GitHub Pages**, com foco em aparência (Taste), Web Interface Guidelines, design sistematizado, melhoria real de componentes a partir de capturas e QA com Playwright.

**Referência visual utilizada:** screenshots reais gerados no GitHub Actions para os estados iniciais web desktop e mobile, da execução `39386119685` (artefato `playwright-web-results`). Nenhuma imagem gerada foi usada como substituta de componentes React ou de código CSS.

## Achados e correções

| Prioridade | Problema observado | Mudança implementada | Verificação |
|---|---|---|---|
| Alta | Editor web muito longo em telas pequenas, sem atalhos entre tarefas | `WorkbenchNav`: cinco links nativos com IDs compartilhados no desktop e web; barra com rolagem horizontal local no mobile | Navegação por clique, foco e fragmento `#studio-*` no Playwright |
| Alta | Alvos de toque pequenos em controles de cortes, legendas e cenas | Regras coerentes de altura mínima 44px e campos 16px em telas de até 600px | Testes 320/375/768/1280/1920 e inspeção visual |
| Média | Foco por teclado não era aplicado uniformemente a selects e textareas | `:focus-visible` compartilhado com alto contraste; bordas no `:focus-within` dos campos | Testes reais de foco em ambos os editores |
| Média | Painéis novos tinham sombra, espaçamento e tipografia divergentes do shell original | `src/editor-polish.css` centraliza tokens de espaçamento/borda/sombra e harmoniza StoryStudio/SubtitleStudio/ProjectExchange | Builds desktop/web e capturas Playwright |
| Média | Página inicial indicava “legendas automáticas” como algo futuro embora o Whisper.cpp já seja opcional | Próxima funcionalidade passa a ser biblioteca sonora | Revisão editorial |
| Baixa | Inscrição da versão na sidebar estava obsoleta (2.0) | Atualização para 2.5; manifesto npm 2.6 beta | Revisão de conteúdo/versão |
| Baixa | Longos nomes de arquivo, roteiro e cenas quebravam o layout | `overflow-wrap: anywhere`, alinhamento `min-width:0` e `text-wrap:balance` | Cobertura responsiva |

## Hierarquia e diretrizes de interação

1. Descobrir: hero web e painel inicial desktop apresentam uma única ação principal.
2. Orientar: navegação curta `Vídeo → Cortes → Legendas → Roteiro → Projeto` dentro do workspace; não altera o projeto e não depende de JS para rolar.
3. Editar: cartões secundários usam borda/sombra sutil e textos de apoio com contraste maior.
4. Concluir: exportação continua no bloco de configuração, mantendo os limites reais de cada motor.
5. Validar: avisos e estados já existentes não são ocultados pelo novo layout; `prefers-reduced-motion` desabilita rolagem suave.

## Critérios de acessibilidade

- Controles da navegação são links semânticos com texto visível; não usar `div onClick` nem simular tabs com ARIA inadequado.
- Estados de foco ficam visíveis mesmo quando a navegação usa rolagem horizontal própria.
- Campos editáveis usam pelo menos 16px em celular para não induzir zoom no Safari.
- Não desativar zoom do navegador; não remover foco visível.
- O trabalho é uma **auditoria de implementação**, não uma certificação completa WCAG, nem substitui validação com leitor de tela humano.

## Automação de QA

```bash
npm run check
npm run qa:visual:web
npm run qa:visual:desktop
npm run test:e2e:web
npm run test:e2e
```

- Novos testes `tests/web/workbench-qa.spec.js` e `tests/e2e/workbench-qa.spec.js`.
- Testar **320, 375, 768, 1280 e 1920px** de largura sem overflow no documento.
- Inspecionar o fragmento após clicar na navegação; verificar foco visível e movimentação reduzida.
- Capturar screenshots do viewport em 375 e 1280px, anexadas aos artefatos do workflow, sem snapshot visual frágil pixel-a-pixel.
- O pipeline geral de CI executa todos os testes além dos novos smoke tests.
